# ZAGATOVKY API

Fastify 5 + Prisma 6 + PostgreSQL. Обслуживает витрину и админ-кабинет.
Папка самодостаточна: её можно вынести в отдельный репозиторий как есть.

## Запуск

```bash
cp .env.example .env
docker compose up -d     # Postgres на 5433
pnpm install
pnpm db:migrate
pnpm db:seed
pnpm dev                 # http://localhost:3000, Swagger на /docs
```

## Маршруты

Всё под префиксом `/api/v1`. Вне префикса только `/health` и `/docs`.

**Публичные** (без авторизации): каталог, карточка товара, подборки, секции главной,
публичные настройки, создание заказа.

**Админские** (`/api/v1/admin/*`, Bearer-токен): товары и наборы, категории, подборки,
конструктор главной, настройки, медиа, заказы, пользователи, журнал, статистика.

## Авторизация

- Короткий access-токен (15 минут) в заголовке `Authorization: Bearer …`.
- Долгий refresh-токен в httpOnly-cookie с путём `/api/v1/admin/auth`.
- Refresh ротируется при каждом использовании. Уже отозванный токен принимается ещё
  30 секунд — иначе две одновременно открытые вкладки выкидывали бы друг друга.
  Токен, отозванный давно, отвергается: это признак кражи куки.
- Подбор пароля отсекается по **неудачным** попыткам (8 за 15 минут на пару
  «IP + почта»). Успешные входы не throttлятся: перебор — это именно неудачи,
  а жёсткий лимит на все входы ломает жизнь команде из одного офиса.
- Роли: `OWNER` (всё, включая команду и удаление товаров), `MANAGER` (каталог, заказы,
  витрина, настройки), `VIEWER` (только чтение).

## Переменные окружения

```
NODE_ENV=production
HOST=0.0.0.0
PORT=3000

APP_URL=https://<витрина>
# Список через запятую: витрина и кабинет живут на разных доменах, нужны оба
CORS_ORIGIN=https://<витрина>,https://<кабинет>

DATABASE_URL=postgresql://…@postgres.railway.internal:5432/railway

JWT_ACCESS_SECRET=…    JWT_ACCESS_TTL=15m
JWT_REFRESH_SECRET=…   JWT_REFRESH_TTL=30d

R2_ACCOUNT_ID=…  R2_BUCKET=…  R2_ACCESS_KEY_ID=…  R2_SECRET_ACCESS_KEY=…
R2_PUBLIC_URL=https://<публичный домен бакета>
```

Секреты сгенерировать так:
`node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"`

Конфиг проверяется zod при старте: если чего-то не хватает, процесс падает со списком
недостающих переменных, а не стартует наполовину рабочим.

## Хранилище фото (Cloudflare R2)

1. R2 → **Create bucket**, например `zagatovky-media`.
2. Откройте бакет → вкладка **Settings** → блок **Public access**.
   Включите **R2.dev subdomain** («Allow Access») — Cloudflare выдаст адрес вида
   `https://pub-a1b2c3….r2.dev`. Его и только его кладите в `R2_PUBLIC_URL`.
   Если подключаете собственный домен (**Custom Domains**) — берите его.
3. R2 → **Manage API tokens** → создать токен с правами Object Read & Write на этот
   бакет. Полученные ключи — в `R2_ACCESS_KEY_ID` и `R2_SECRET_ACCESS_KEY`.
   `R2_ACCOUNT_ID` виден в URL панели Cloudflare.

> **Не перепутайте адреса.** `https://<account>.r2.cloudflarestorage.com` — это
> S3-эндпоинт для записи, он требует подписи запроса и посетителю отдаёт
> `400 Authorization` вместо картинки. Публичный адрес всегда либо `*.r2.dev`,
> либо ваш собственный домен. Сервер предупреждает об этой ошибке при старте.

Пока переменные пустые, API работает полностью, только загрузка фото отвечает 503,
а витрина показывает буквенные заглушки вместо снимков. Кабинет об этом честно
предупреждает на странице медиатеки.

Что происходит при загрузке: поворот по EXIF, ограничение большей стороны 2000px,
конвертация в WebP и генерация LQIP-плейсхолдера для плавного появления на витрине.

## Деплой

`Dockerfile` — multi-stage, применяет `prisma migrate deploy` на старте, так что новый
деплой сам приводит схему БД в порядок. Проверка живости — `GET /health`.

```bash
docker build -t zagatovky-api .
```

Первый деплой на пустую базу: после старта выполнить `pnpm seed:prod`
(или `node dist/prisma/seed.js`) — создаст категории, бейджи, стартовый каталог,
секции главной и учётку владельца из `SEED_OWNER_EMAIL` / `SEED_OWNER_PASSWORD`.
Пароль сразу смените в кабинете.

## Данные

Цены — целые тенге (`Int`), без копеек. Весь контентный текст двуязычный: пары полей
`*Ru` / `*Kk`, сервер отдаёт обе версии, витрина выбирает нужную на клиенте — поэтому
переключение языка мгновенное.

Ключевые сущности: `Product` (`type = SIMPLE | BUNDLE`, набор — самостоятельный товар
со своей ценой), `BundleItem` (состав набора), `MediaAsset` (общая медиатека),
`Order` + `OrderItem` (снимок названий и цен на момент заказа) + `OrderEvent` (история
статусов), `HomeSection` (конструктор главной), `SiteSetting`, `AuditLog`.

Номер заказа выдаётся автоинкрементом (`Order.seq`) и показывается как `ZG-000123` —
без гонок и без лишних запросов.
